📌 1. Executive Summary

Core Problem: Teachers spend up to 140 hours per school year just on marking assignments — not including lesson planning or parent communication. This hidden workload swallows evenings and weekends, leading to burnout and reduced time for actual teaching.

GCR Simplified is a cross-platform desktop application (Windows & macOS) designed to automate the entire assignment evaluation pipeline for teachers. It combines submission tracking, AI-powered plagiarism detection, intelligent answer evaluation, rubric-based scoring with explainable feedback, and Excel report generation — all within a clean, teacher-friendly interface.

🎯 Key Value Propositions
  1. Submission Tracking Automation — Instantly identifies who submitted and who didn't, with automated nudge reminders.
  2. Cross-Student Plagiarism Detection — Detects copied assignments between students using multi-layered similarity algorithms (not just web plagiarism).
  3. AI Answer Evaluation — Uses Large Language Models (LLMs) to evaluate open-ended responses against teacher-defined rubrics and model answers.
  4. Explainable Scoring — Every score comes with a clear, human-readable justification referencing specific rubric criteria.
  5. One-Click Excel Export — Generates formatted grade sheets with scores, feedback, and integrity flags, saved to teacher's chosen location.

🏗️ 3. Feature Architecture

3.1 Module 1: Submission Tracker

Purpose: Ensure no student slips through the cracks.

  • Roster Import: Upload CSV/Excel with student names, roll numbers, emails.
  • Auto-Match: Matches submitted files to roster using filename patterns (e.g., RollNo_Name_Assignment.pdf).
  • Missing Report: One-click view of unsubmitted students with option to export list or send reminder.
  • File Format Support: PDF, DOCX, TXT, Images (JPG/PNG for handwritten), ZIP bulk uploads.

3.2 Module 2: Integrity Checker (Plagiarism)

Purpose: Catch cheaters who copy from friends — the most common form of classroom plagiarism.

  • Intra-Class Similarity: Compares every submission against every other submission in the batch.
  • Multi-Layer Detection:
    • Layer 1 — Text Fingerprinting (n-grams): Fast exact-match detection using Winnowing algorithm.
    • Layer 2 — Semantic Similarity: Sentence embeddings (e.g., all-MiniLM-L6-v2) to catch paraphrased copying.
    • Layer 3 — Stylometry: Writing style analysis to flag sudden style shifts (indicates ghostwriting or AI generation).
  • Clustering View: Groups suspicious submissions into "copy clusters" with similarity percentages.
  • Side-by-Side Diff: Highlighted comparison of two submissions with color-coded matching blocks.

3.3 Module 3: AI Evaluation Engine

Purpose: Consistent, rubric-aligned grading at scale.

  • Rubric Builder: Teacher defines criteria (e.g., "Thesis Clarity — 5 marks", "Evidence — 5 marks", "Grammar — 3 marks").
  • Model Answer Upload: Teacher can provide a reference/model answer for relative scoring.
  • LLM Evaluation Pipeline:
    1. Extract text from submission (OCR if image/PDF).
    2. Chunk long answers into semantic segments.
    3. Send to LLM with rubric, model answer, and evaluation prompt.
    4. Parse structured JSON response: {"criteria": [...], "total_score": X, "feedback": "..."}
  • Explainability: Every score includes a 2–3 sentence rationale tied to specific rubric points.
  • Teacher Override: Teachers can click any score, see AI reasoning, and adjust — the system learns from corrections.

3.4 Module 4: Reporting & Export

Purpose: Zero-friction report generation.

  • Excel Workbook: Auto-formatted with:
    • Sheet 1: Summary (class average, highest/lowest, submission rate)
    • Sheet 2: Grade Sheet (Roll No, Name, Score per criteria, Total, Grade, Remarks)
    • Sheet 3: Integrity Report (similarity scores, flagged pairs, action taken)
    • Sheet 4: Feedback Log (full AI feedback per student for reference)
  • Custom Save Location: Teacher picks folder; file auto-named: ClassName_AssignmentName_Date.xlsx
  • Template Support: Teachers can save their preferred Excel template for future assignments.

🔍 5. Plagiarism Detection Engine (Deep Dive)

Critical Insight: Most classroom plagiarism is not from the internet — it's student-to-student copying. Your app must excel at intra-class similarity detection, which most tools ignore.

5.1 Multi-Layer Detection Architecture

Layer 1: Fingerprinting (Winnowing Algorithm)

What it does: Detects exact and near-exact copying, even with minor edits.

  • Break text into k-grams (overlapping sequences of k words, e.g., k=5).
  • Hash each k-gram using a rolling hash function.
  • Select a subset of hashes using Winnowing (selects minimum hash in each window) to create a compact fingerprint.
  • Compare fingerprints between all student pairs using Jaccard similarity.
  • Complexity: O(n) per document, very fast for 100+ submissions.
# Pseudocode: Winnowing Fingerprinting
def winnow(text, k=5, w=4):
    tokens = preprocess(text)  # lowercase, remove punctuation
    hashes = [rolling_hash(tokens[i:i+k]) for i in range(len(tokens)-k+1)]
    fingerprints = set()
    for i in range(len(hashes) - w + 1):
        window = hashes[i:i+w]
        min_hash = min(window)
        fingerprints.add(min_hash)
    return fingerprints

similarity = jaccard(fingerprints_a, fingerprints_b)

Layer 2: Semantic Similarity (Sentence Embeddings)

What it does: Catches students who paraphrase or reorder sentences.

  • Convert each answer into sentence embeddings using all-MiniLM-L6-v2 (384-dim vectors).
  • Compute cosine similarity between embedding vectors of different students.
  • Flag pairs with similarity > 0.85 (threshold configurable by teacher).
  • Advantage: "The quick brown fox" and "A fast auburn fox" will have high similarity despite different words.

Layer 3: Stylometric Analysis

What it does: Flags when a student's writing style suddenly changes (indicates ghostwriting or AI generation).

  • Extract features: average sentence length, lexical diversity (type-token ratio), punctuation frequency, function word distribution.
  • Compare current submission against student's historical submissions.
  • Significant deviation (> 2 std dev) triggers a "Style Anomaly" flag.

5.2 Clustering & Visualization

  • Graph-based clustering: Students are nodes; edges represent similarity > threshold. Connected components form "copy clusters."
  • Force-directed graph view: Visual map where clustered nodes pull together — teachers instantly see cheating rings.
  • Pairwise diff viewer: Color-coded side-by-side comparison with matching phrases highlighted.

5.3 Thresholds & False Positive Control

Reporting Balance: The system should default to conservative thresholds to avoid false accusations. Teachers can tighten thresholds if they want stricter checking.
  • Default Fingerprint Similarity Threshold: 40% (flags for review, not accusation)
  • Default Semantic Similarity Threshold: 80%
  • Confidence Labels: "High Confidence" (>70%), "Medium Confidence" (40–70%), "Low Confidence" (<40%)

🤖 6. AI Grading Engine (Deep Dive)

6.1 Evaluation Prompt Engineering

The quality of AI grading depends entirely on the prompt. Here is the recommended structured prompt template:

You are an experienced teacher grading a student assignment.

ASSIGNMENT QUESTION:
{question_text}

MODEL ANSWER (for reference):
{model_answer}

RUBRIC:
{criteria_json}

STUDENT ANSWER:
{student_answer}

INSTRUCTIONS:
1. Evaluate the student answer against EACH rubric criterion independently.
2. Assign a score for each criterion (0 to max marks).
3. Provide a 1-2 sentence justification for each score, citing specific evidence from the student answer.
4. Calculate the total score.
5. Provide an overall summary feedback (2-3 sentences) highlighting strengths and 1 specific improvement area.
6. Be fair but strict. Partial credit is allowed. If the answer is blank or irrelevant, score 0.

OUTPUT FORMAT (strict JSON):
{
  "criteria": [
    {"name": "...", "max_marks": 5, "awarded": 3, "justification": "..."}
  ],
  "total_score": 15,
  "max_score": 20,
  "overall_feedback": "...",
  "confidence": "high|medium|low"
}

6.2 Handling Different Question Types

Question Type AI Approach Notes
Short Answer (1–3 lines) Direct LLM evaluation with keyword matching backup Fast, high accuracy
Long Essay Chunk into paragraphs → evaluate per rubric criterion → aggregate Prevents context window overflow
Mathematical / STEM LaTeX parsing + symbolic math check (SymPy) + LLM reasoning Hybrid approach recommended
Code Assignments AST parsing + test case execution + LLM code review Requires sandboxed execution
Handwritten (Image) OCR (Tesseract/Azure) → text → standard pipeline OCR error rate affects grading accuracy

6.3 Teacher-in-the-Loop Learning

  • Override Tracking: When a teacher changes an AI score, the system stores the triplet: (student answer, original AI score, teacher score).
  • Few-Shot Improvement: These corrections are added as few-shot examples in future prompts for that teacher's assignments.
  • Rubric Refinement Suggestions: If teachers consistently override a particular criterion, the system suggests rubric rewording for clarity.

🎨 7. UI/UX Design for Teachers

Design Philosophy: Teachers are not power users. They are time-poor, stressed, and need tools that feel familiar. Every extra click is friction. Every unfamiliar pattern is a barrier.

7.1 Core Design Principles

🧹 Simplicity & Clarity

No clutter. No jargon. One primary action per screen. Use familiar metaphors: "Gradebook", "Red Pen", "Class List".

🔄 Consistency

Same button styles, same color meanings (red = flag, green = done, amber = pending), same navigation across all screens.

⚡ Instant Feedback

Progress bars for batch operations. Toast notifications for saves. No silent failures. Teachers must trust the system.

♿ Accessibility

WCAG 2.1 AA compliance. Minimum 4.5:1 contrast. Keyboard navigation. Screen reader support. Adjustable font sizes.

📱 Responsive Layout

Works on 13" laptops (common teacher device) up to 27" monitors. Collapsible sidebars. Scalable content.

🛡️ Error Forgiveness

Undo for grade changes. Confirmation for destructive actions. Auto-save every 30 seconds. Recovery from crashes.

7.2 Recommended Screen Flow

  1. Home / Dashboard — Recent assignments, quick stats ("3 assignments pending grading"), one-click "New Assignment".
  2. Assignment Setup — Upload question paper → Define rubric (visual drag-and-drop) → Upload model answer (optional) → Import roster.
  3. Submission Inbox — Drag-and-drop student files → Auto-match to roster → Visual indicators: ✅ Submitted, ❌ Missing, ⚠️ Unmatched.
  4. Integrity Review — Cluster graph view → Click cluster to see pairwise diffs → Teacher marks "Confirmed Cheat" or "False Positive".
  5. Grading Workspace — Split pane: Student answer (left) | AI scores & feedback (right) | Teacher can edit any score with one click.
  6. Export & Share — Preview Excel → Choose save location → One-click generate → Open folder button.

8.2 Data Storage Strategy

💾 Local-First Architecture
  • SQLite for structured data: rosters, assignments, scores, rubrics, teacher preferences.
  • File System for blobs: student submissions (PDFs, images), exported Excel files.
  • Local Embeddings Store: FAISS or Annoy index for fast similarity search across submissions.
  • Why local-first? Privacy (student data never leaves the machine), speed (no network latency), offline capability.
☁️ Optional Cloud Layer (Phase 2)
  • Encrypted backup of gradebooks to teacher's Google Drive / OneDrive.
  • Cross-device sync for teachers who use multiple computers.
  • Institutional dashboard for principals (aggregated anonymized stats).

8.3 Processing Pipeline

Step 1: INGEST
  └─► Teacher uploads files (drag-drop or folder select)
  └─► System extracts text (PDF → pdfplumber, Image → Tesseract OCR, DOCX → python-docx)
  └─► Auto-match filenames to roster using regex patterns

Step 2: INTEGRITY CHECK
  └─► Run Winnowing fingerprinting on all text pairs → similarity matrix
  └─► Run sentence embeddings on all pairs → semantic similarity matrix
  └─► Aggregate: weighted average of both scores
  └─► Cluster graph generation (connected components)
  └─► Teacher reviews flagged pairs in visual diff viewer

Step 3: AI EVALUATION
  └─► For each unmatched submission:
      ├─► Chunk text if > 2000 words
      ├─► Build evaluation prompt with rubric + model answer
      ├─► Call LLM API (or local model)
      ├─► Parse JSON response
      └─► Store scores + feedback in SQLite
  └─► Teacher reviews in Grading Workspace, overrides if needed

Step 4: REPORTING
  └─► Aggregate all scores per student
  └─► Calculate class statistics (mean, median, std dev, grade distribution)
  └─► Generate Excel workbook using rust_xlsxwriter
  └─► Save to teacher-specified path
  └─► Open file or folder on completion

🔒 11. Compliance & Privacy

Critical: Student data is highly sensitive. A single privacy misstep can destroy trust and invite legal action. Design privacy into the architecture from day one.

11.1 Regulatory Requirements

Regulation Applies To Key Requirements for GCR
FERPA (US) US K-12 & Higher Ed Local storage default; no cloud upload without explicit consent; data encryption at rest
GDPR (EU) EU teachers & students Right to deletion, data portability (Excel export helps!), privacy by design, no unnecessary data collection
COPPA (US) Students under 13 No account creation for students; teacher acts as data controller; no behavioral tracking

11.2 Privacy-By-Design Features

  • Local-First Default: All student submissions, grades, and rubrics stored on teacher's machine. No cloud required.
  • Optional Cloud: If cloud sync is added, use teacher's own storage (Google Drive, OneDrive) with client-side encryption.
  • LLM Privacy Mode: Option to use local LLM (e.g., Llama 3 via Ollama) instead of cloud API for schools with strict data policies.
  • No Student Accounts: Teachers manage everything. Students never interact with the app — eliminating COPPA complexity.
  • Auto-Purge: Option to automatically delete raw submission files after Excel export, keeping only grades.
  • Audit Log: Track who graded what and when (useful for grade disputes).

🚀 Final Recommendations

  1. Start with the MVP stack: Tauri + React + SQLite + Google Gemini API. This gives you the fastest path to a working prototype with professional quality.
  2. Build for one subject first: Focus on essay/short-answer grading for humanities. STEM (equations, code) adds significant complexity — defer to Phase 2.
  3. Recruit 5 beta teachers immediately: Their feedback during development is worth more than any market research. Offer free lifetime Pro access in exchange for weekly feedback sessions.
  4. Prioritize plagiarism over AI grading in MVP: Intra-class cheating detection is your unique differentiator. Nail this first — it builds trust. AI grading can be refined iteratively.
  5. Never auto-finalize grades: Every AI score must be labeled "Suggested" until the teacher clicks "Approve." This is your legal and ethical shield.
  6. Invest heavily in Excel export quality: Teachers live in Excel. A beautiful, well-formatted, auto-summarized Excel file will generate more word-of-mouth than any feature.
